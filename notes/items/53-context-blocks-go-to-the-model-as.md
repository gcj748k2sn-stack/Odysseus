# 53. Context blocks go to the model as extra user turns at the start of the chat

Open item, moved here from `notes/todo.md` on 2026-10-07 so the dashboard stays short. Its row in the [todo.md](../todo.md) index carries the current status; this file is the full record.

**Found 2026-10-04 alongside item 52. Design only — nothing built.**

- **Layout today, from code (not a captured prompt — nothing logs the message array):**
  1. `routes/chat_helpers.py` `build_chat_context`: `messages = preface + history`. The preface from `ChatProcessor.build_context_preface` (`src/chat_processor.py`) is `[system: preset prompt?] [system: UNTRUSTED_CONTEXT_POLICY]` then **user-role** `untrusted_context_message` blocks: pinned memory, retrieved memory, RAG documents, web results (chat mode), fetched URLs, and in agent mode the **skills index**. They sit **before the first real user message.**
  2. `src/agent_loop.py` `_build_system_prompt` merges the system messages, then inserts **more user-role blocks immediately before the latest user message**: active document, email draft/style, integrations, MCP descriptions, **skills again** (`_skill_index_block` plus matched skills, with *"treat them as authoritative guidance"*), and the date/time.
- **What it does to the model.** Thinking blocks mention the wrappers in **15 of 268** recorded replies. Some are the intended use (Celsius from a saved preference). Several read them as the user's words or as earlier turns: `845a025b` *"The user has provided a block labeled UNTRUSTED SOURCE DATA"*; `2ebdd27a` *"The UNTRUSTED_SOURCE_DATA block shows this was attempted before"*; `0829a3d2` *"First turn showed system prompt about UNTRUSTED_SOURCE_DATA — Second turn asked me to fetch that from memory."* Bonsai 2 raised the Arduino skills unprompted in a greeting (`cdb89980`).
- **What it does to speed.** Memory retrieval is per message (`_select_pinned_memories`, `_hybrid_retrieve` on the new message), and RAG / web results are per message by nature. Sitting at the *start*, any change re-keys the whole conversation for llama.cpp / LM Studio prefix caching — the opposite of what the comments in both files say the layout is for (#2927: per-turn content belongs at the tail). Separate cause, same symptom: tool RAG sends a different tool set per message (6 → 8 → 7 in `cdb89980`), and the template renders tools ahead of the history. Not part of this item.
- **Proposed change (A):** one context message, built in a fixed order — stable parts first (skills index, memory, RAG/web/URL pages, active document, integrations/MCP) and the date/time last — wrapped **once** in `untrusted_context_message` with a header saying it is supplied by Odysseus and not written by the user, inserted **immediately before the latest user message**. The skills index is sent **once**, without *"treat them as authoritative guidance"*. `UNTRUSTED_CONTEXT_POLICY` stays in the system message.
  - **Alternative (B):** append the same block to a request-time copy of the latest user message (never the persisted one). Cannot be read as a separate turn at all, but it puts retrieved text inside the user's own turn, which weakens the boundary the wrapper exists for. **Prefer A; try B only if A measurably still reads as a turn.**
- **Expected effect, to be measured, not assumed:** history and system become byte-stable across turns, so a follow-up re-reads only the context block and the new message. On Bonsai 2 (~70 tok/s prefill) that is the difference between ~40–60 s and a few seconds before the first token on turns where the tool set does not change.
- **Tests that pin the current layout and will need deliberate updates:** `test_skill_index_prompt_injection.py`, `test_chat_processor_pinned_memory.py`, `test_chat_processor_web_search.py`, `test_chat_helpers.py`, `test_kv_cache_invalidation_2927.py` (should get *stronger* — assert the history prefix is identical across two turns with different retrieved memory), and the security suite's untrusted-wrapper checks. **Risk:** the security wrapper is the point of these blocks — every block must still arrive inside `GUARD_OPEN`/`GUARD_CLOSE`, and no user-editable text may reach the system role.
- **Observables, named before building:** (1) a debug log line per round listing the message layout as roles + labels, so the layout is checkable from `app.log`; (2) llama-server `cache_n` on a follow-up turn ≈ the previous prompt length (with the tool set held fixed); (3) over the next ~20 turns, thinking that refers to the wrappers as turns drops from the 15/268 baseline.
- **Paths to cover:** chat mode and agent mode, incognito (no memory/skills, already handled), compare mode, group chats, research spin-offs.
