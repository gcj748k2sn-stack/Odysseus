# 50. LM Studio's loaded context is invisible to Odysseus, so a long turn outgrows it

Open item, moved here from `notes/todo.md` on 2026-10-07 so the dashboard stays short. Its row in the [todo.md](../todo.md) index carries the current status; this file is the full record.

---

**Found 2026-10-04 from session `933f8674` (*"what is the current value of gold in euro and how did it change over the last year?"*) — the first chat on LM Studio after the switch.** 14 rounds, 7 min, `qwen/qwen3.5-9b` loaded at **32,768**. The answer quoted **2,253.00 EUR** and **2,454.16 USD (Kitco)** and concluded gold was *"over 50% below its peak"*. **Neither number appears in any page the turn fetched** (grep of `data/cache/content/`). The pages said *"3 683,61 €"* (BullionByPost, week) and *"As of Oct 4, 2026 … 4,140.520 USD"* (TradingView). The thinking had 3,671.70 € at round 4; the invented figures first appear after round 11. The last-year half of the question was never answered.

- **Mechanism, from both logs:**
  - `src/model_context.py` returned **131072** for `qwen/qwen3.5-9b` — the known table's `qwen3` row. LM Studio answers `/slots` with a 200 that is not a list, and its OpenAI-compatible `/v1/models` carries no context field, so nothing reported the real window. `app.log` logged the same 131072 for this model on 2026-10-02.
  - Nothing trimmed. The prompt grew **10,540 → 39,659 tokens** (LM Studio's counts; Odysseus's `prompt_tokens` leaves out the ~5.7k of tool schemas — 38 tools on this turn).
  - LM Studio's per-model *Context Overflow* was **Truncate Middle**. `~/.lmstudio/server-logs/2026-10/2026-10-04.1.log`, rounds 12–14: *"pre-processing the '34724' / '37916' / '39659' token prompt by removing '22510' / '25702' / '27445' tokens from the middle, starting at token idx (n_keep) '8340'"*. Each round kept the first 8,340 tokens (system prompt, tools, question) and the last ~3,900, so **the final answer was written from 12,214 of 39,659 tokens.**
  - Before the cut, a separate misreading in the same answer: BullionByPost's *"2 537,88 € ( 223,84 %)"* — the 10-year change — was read as *"1-year ago price: 3,537.88 €"* (European number format). Not this item; recorded so it is not mistaken for one.
- **Why 32,768 and not 65,536 like the Ollama tag:** LM Studio's own fit at load (same log, 11:40:16): `fitted=32,768 working_set=11.84GiB reserve=3.00GiB safe_ceiling=8.84GiB baseline=5.54GiB … estimated_peak=8.84GiB`, ≈104 KiB per token (KV 32 + prompt inputs 8 + attention 64). 32,768 is LM Studio's ceiling on this Mac, not a preference.
- ✅ **Discovery half fixed 2026-10-04.** `_lmstudio_loaded_context` in `src/model_context.py` reads LM Studio's native `GET /api/v1/models` after `/slots` (local endpoints only, never cached, so a reload is picked up on the next lookup). An instance whose identifier is the requested name wins; otherwise the smallest loaded instance of the matching key. **Listed but not loaded returns `DEFAULT_CONTEXT, known=False`, not the table** — a just-in-time load uses the saved default, which the API does not expose — so that one turn budgets at the conservative 6,000. The response shape comes from LM Studio's docs and the existing `model_capability_readers/lmstudio.py`; **it is not a recorded response.**

- 🔴 **In-turn half OPEN — investigated 2026-10-04, not built.** Odysseus trims only at turn start: `maybe_compact` + `trim_for_context` in `routes/chat_helpers.py`, and the soft trim at `agent_loop.py` prep. **Nothing trims between rounds.** Measured, with every number re-derivable from `app.log*` and LM Studio's server log:
  - **Calibration.** On the 20 paired LM Studio rounds (10-02 and 10-04), real tokens ≈ **0.92–0.94 × Odysseus's `estimate_tokens`** for message text, **plus the tool schemas, which the estimate never counts.** On the gold turn the gap was 5,729 tokens at round 1 with 38 tools. `estimate_tokens` therefore runs about 8% high on web text and several thousand low overall when many tools are sent. **The loop already holds the exact figure:** `last_round_input_tokens` is the provider-reported prompt of the previous round, schemas included. ⚠️ Under *Truncate Middle* it reports the size **after** the cut: this turn's recorded `input_tokens` = 269,934 = rounds 1–11 + 3 × 12,214, to within 11 tokens.
  - **What a round adds** (all 511 agent turns in `app.log*`, 2026-07-12 → 10-04, real-token estimate): `web_search` median **2,830** (p90 2,955 — its output is capped at 10,000 chars), `web_fetch` median 743 (p90 2,839), `edit_document` 1,713, `create_document` median 3,089 with p90 8,375 and **max 30,213 in one round** (2026-07-30 11:51: the model's own 54 KB document in its tool-call arguments). On the gold turn only **~15 %** of the tool output repeated earlier output, so de-duplication alone does not help much.
  - **Fixed overhead.** The gold turn sent **38 tool schemas (~6k tokens, a fifth of the window)** for a price question; tool RAG picked `manage_tokens`, `list_models` and browser automation (`mcp__builtin_browser__*`). The 10-02 LM Studio turn sent 7.
  - **Scope.** Of 511 turns, **6 (1.2 %)** exceed 32,768 minus a 4,096 output reserve at some round, and **all 6 cross it during the turn, none at round 1.** At 65,536, **none do** (peak ≈42.3k). So this is a 32k-window problem, and the turn-start fix above cannot reach any of the 6.
  - **Under *Stop at Limit*** LM Studio is reported to reject an oversized prompt with *"The number of tokens to keep from the initial prompt is greater than the context length…"* (seen in other clients; **not yet observed here on 0.4.25**). Odysseus ends the turn on a stream error, so **a gold-like turn now fails visibly at round ~12 and its gathered research is discarded.**

- **Options, replayed against the recorded rounds (W = 32,768):**
  - **(1) No code: a 64k window.** Ollama holds 64k in 6.7 GB (~19 KiB/token measured); LM Studio's MLX engine budgets ~104 KiB/token, 64 KiB of it attention scratch. **Hypothesis, untested:** a GGUF build of Qwen3.5-9B on LM Studio's llama.cpp runtime (2.51.0 installed) fits 65,536 like Ollama does. Check LM Studio's load estimate, then whether later rounds stay fast. If it holds, **0 of 511 recorded turns overflow.**
    - ✅ **Tested 2026-10-04 18:30 — the hypothesis holds.** The Q4_K_M GGUF on LM Studio's llama.cpp runtime loaded at **65,536** (`lms load … -c 65536`, reported back by `/api/v1/models`) and processed a **27,757-token prompt at 200 tok/s** prefill, 19.0 tok/s decode. It is also the fastest engine for agent rounds (prefill 221–226 tok/s vs MLX 155–158 and Ollama 219–222 — [qwensetup.md](../qwensetup.md), *Engine benchmark*), and since 18:24 it is the variant Odysseus's `qwen/qwen3.5-9b` loads. ✅ **Set and verified live 18:41:** load context 65536 in My Models (`user-concrete-model-default-config/qwen/qwen3.5-9b.json` now `llm.load.contextLength = 65536`); LM Studio's log `n_ctx_slot = 65536`; `app.log` `LM Studio reports loaded context 65536` and `prep_done … context_length=65536` on the next turn. **With this, 0 of the 511 recorded turns would have overflowed (peak ≈42.3k).** The in-turn guard is still not built, so a turn that grows past ~61k would still hit *Stop at Limit* and fail visibly — mitigated, not fixed. Memory pressure at 64k during a long agent turn not yet observed.
  - **(2) Predictive force-answer — an acting guard ([`CLAUDE.md`](../../CLAUDE.md) §3).** Before round N, if `prompt(N) + 3,000 (one more web round) + 4,096 (reply) > window`, run N as the existing `_force_answer` round: no tools, so the schemas drop out, with grace synthesis if the model writes nothing. Base `prompt(N)` on `last_round_input_tokens` plus the estimate of what was appended since, not on `estimate_tokens` alone. **Replay: it fires in 9 of 511 turns; 5 of the 6 overflows get an answer round that fits; 3 of the 9 would never have overflowed** (early answers). The gold turn answers at round 8, with the BullionByPost pages already in context. Cannot save a turn where one round jumps ~30k.
  - **(3) Stub the document body after a successful `create_document` / `update_document`.** Replace the tool-call arguments in history with a reference (title, id, size). This targets the one turn (2) cannot save. ⚠️ A later `edit_document` find/replace then needs the text: check that the edit path reads the stored document and not the history.
  - **(4) React to the overflow error:** retry the round once as a force-answer round. Exact — it fires only on a real overflow — but it relies on the server raising an error (LM Studio under *Stop at Limit* should; Ollama truncates silently). Verify the error text on 0.4.25 first.
  - **(5) Count schemas and the real reply at turn start.** `trim_for_context` keeps back 512 tokens in `routes/chat_helpers.py` and 2,048 in the agent prep, against `max_tokens` 8,192, and neither counts schemas. At 32k with the auto budget (0.85 × 32,768 = 27,852 estimate ≈ 25.6k real), a turn can start at ~31.7k real with 38 tools.
  - **(6) Send fewer tools** for a plain web question. Separate lever: about 4–5k back on every round of such turns. **The browser half is item 51** (built 2026-10-04): the browser's 31 schemas and its prompt text no longer go out unless the request asks for a browser. Other top-k retrieval noise (`manage_tokens`, `list_models` on the gold turn) is not addressed.
