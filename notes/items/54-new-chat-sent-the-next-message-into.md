# 54. "New Chat" sent the next message into the previously open chat

Open item, moved here from `notes/todo.md` on 2026-10-07 so the dashboard stays short. Its row in the [todo.md](../todo.md) index carries the current status; this file is the full record.

---

**Reported 2026-10-04 by the maintainer** (*"i'm clicking new chat each time and it opens the front page. at first it doesn't even show it's the same chat"*), **reproduced and fixed the same evening.**

- **Evidence in `app.db`:** no session was created between 19:53 and 21:26 although New Chat was clicked several times; the 20:19 and 20:46 sends landed in *"Macrolepiota Procera Overview"* (`2e3ff29e`, created 10-02) — the first one routed to that chat's stored model, `prism-ml/bonsai-27b` on LM Studio, which was down. *"hi mark"* (`717636da`) holds 22 messages from what the maintainer ran as separate chats. This is also why models "remembered" earlier greetings (see items 52/53) and why an old chat's wrong content steered Bonsai 2 (*"giant milk cap"*, `2e3ff29e`).
- **Mechanism.** Browsers key ES modules by full URL, query included. `static/app.js` imported `./js/sessions.js?v=20260722ctxheader4`; `chat.js` and 14 other modules imported `./sessions.js`. **Two copies of `sessions.js` ran, each with its own `currentSessionId` / `_pendingChat`.** The New Chat button (wired in `app.js`) cleared copy A; the send path (`chat.js`) read copy B. After a page's first send, copy B re-renders the sidebar, so row clicks set B's current chat — and New Chat never touched it.
- **Reproduced live 2026-10-04 ~21:26** in the agent's built-in browser (Chromium), logged in, with `/api/chat_stream` intercepted so nothing reached a model or a chat: `window.sessionModule !== await import('/static/js/sessions.js')`; after opening `2e3ff29e` and clicking New Chat, copy A said no chat, copy B said `2e3ff29e`, and the send was addressed to `2e3ff29e`.
- **Scope:** 11 modules were loaded under more than one URL (`sessions`, `chatRenderer` ×3, `settings` ×3, `models`, `memory`, `gallery`, `tasks`, `modalManager`, `compare/index`, `research/panel`, `research/jobs`, …). The same class had already bitten `cookbook.js` (two `_envState` objects) and was fixed for that one file only, with a comment in `app.js`.
- **Fix:** removed every `?v=` from JS module specifiers — 52 in 15 files (`static/app.js`, `static/index.html` module tags and `modulepreload` links, and 13 modules). Safe because `_RevalidatingStatic` (`app.py`) already serves `.js` with `Cache-Control: no-cache`, and `static/sw.js` fetches JS network-first; its precache list was already unversioned. The `app.js` comment now covers every module. CSS `?v=` left alone (no module identity).
- **Tests:** `tests/test_static_module_single_url.py` (4) — scans the import graph and `index.html` module tags: every module has exactly one URL, no module URL carries a query, a negative control that the scanner flags the exact `app.js`/`chat.js` split, and a pin on the `no-cache` header the fix relies on. **Mutations:** all 15 files restored → 2 fail (lists all 11 split modules); only `app.js`'s `sessions.js` import re-versioned → 2 fail. **Sandbox suite:** 5,890 passed, the same 11 environment failures as item 52.
- **Verified live after the fix (same pane, sends intercepted):** one copy (`sameInstance: true`, 0 of 153 loaded JS URLs versioned); open `2e3ff29e` → New Chat → send went to a **new** chat; open `2e3ff29e` → send went to `2e3ff29e` (opening a chat still works).
- ⚠️ **Side effects of the verification:** three empty chats were created by the test sends (*"qwen3.5-9b 21:26:02"*, *"21:33:21"*, *"21:33:36"*, 0 messages each). Delete them from the sidebar.
- 🔍 **Found during verification, not fixed:** `static/js/chat.js:3764` reads `streamingTTS` in the outer error handler, but it is a `const` declared inside the `try` at :1900 — so any failed `/api/chat_stream` request throws `ReferenceError: streamingTTS is not defined` before the error is shown or streaming state is cleared. Seen on every intercepted send. Probably why a dropped connection can leave the UI stuck; not measured.
