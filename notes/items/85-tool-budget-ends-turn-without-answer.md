# 85. The tool budget ends the turn without an answer

Open item, filed 2026-10-13. Its row in the [todo.md](../todo.md) index carries the current status; this file is the full record.

---

**What happens.** When a turn reaches `agent_max_tool_calls`, `stream_agent_loop` emits `budget_exceeded` and `break`s (`src/agent_loop.py`, the `if budget_hit: break` after the tool loop). The model never gets a round to use what it gathered, so the user sees only the turn report's *"I ran `web_fetch`, `web_search` and then stopped without producing an answer"* (item 8's reporting half). The loop-breaker in the same function already handles its own stop correctly: it sets `_force_answer`, appends a system message (*"write your best final answer NOW from the information already gathered, or … say plainly what's blocking you"*) and runs **one round with no tools**. The budget path does not.

**Evidence, 2026-10-13 benchmarks (Qwen 3.5 9B, LM Studio and Ollama).** At least 8 task runs ended `budget_exceeded` with no answer after 19–26 tool calls: webhard 08:52 (1), filter A/B rounds 1–3 (off 2, on 3), web phase Ollama (1), research (1, `res_gold2000`). Same tasks with and without the relevance filter, so the filter is not the cause. The searches were not empty: `bench_web_seen.py` shows `res_gold2000` was shown 295 mostly relevant results. Run dirs in [benchmark.md](../benchmark.md) *Results*. `agent_max_tool_calls` on the M1 is **20** (read 2026-10-13; default 0 = unlimited). The check runs before each call, so the budget is hit when the model asks for call 21; several calls per round explain the 19–26 seen.

**Not item 8.** Item 8 is the model stopping by itself after gathering; here Odysseus stops it. Item 8's history decides the design: its active half (*"finish the job NOW using the appropriate tool"*) was **reverted** after a retry wiped a 6,186-character document (*The agent gathers information, then stops*). Telling a model to act, with tools available, resolves to the most destructive call at hand.

## Built 2026-10-13 (uncommitted → see the row for the commit)

- `src/budget_answer.py` (`should_answer`, `pad_results`, `answer_message`) and a call site at `if budget_hit:` in `stream_agent_loop`: results of the calls that ran are fed back, every cut call of the batch gets *"Not run: the tool-call budget for this turn was reached."*, the system message asks for the final answer from what was gathered (or one or two sentences on what is missing), `_force_answer` is set, one more round runs. No answer round when the budget runs out on the last allowed round (plain stop, as before).
- **Also changed:** the intent-without-action nudge (*"DO IT NOW: emit the actual function call"*) no longer fires in a force-answer round; it asked for a tool call in a round that has no tools, and cost up to two extra rounds. This applies to the loop-breaker's answer round too.
- **Not changed, worth knowing:** a force-answer round still runs the *auto-create document from a ≥ 30-line code block* fallback, so a long code answer in that round can create a document. It creates, never edits or empties; pre-existing for the loop-breaker.
- **Tests:** `tests/test_budget_answer.py` (9, driving the real loop with a scripted model that keeps asking for web searches): one answer round with **no tool schemas** in the request; every `tool_call_id` of the cut batch answered; tool calls in the answer round discarded, nothing executes after the budget, exactly one extra round; budget 0 and a turn that answers in time unchanged (negative controls); no answer round on the last round; a promise-shaped answer does not start another round. **Mutations, 6 of 6 caught:** call site removed (4 tests fail), tools left on in the answer round (4), cut calls not answered (2), last-round check dropped (2), intent-nudge exemption removed (1), answer message dropped (1). **Sandbox full suite** (Python 3.13 scratch venv, Linux, `-n 4`): 8,096 passed, 4 skipped, 1 failed — `test_integrations_url_join.py::test_api_call_root_path_has_no_trailing_slash`, *"URL rejected: host does not resolve"*: the sandbox has no DNS for its test host; unrelated to this change (integrations URL code). M1 suite owed. `should_answer`'s *already forcing* condition cannot be reached (an answer round discards tool calls, so the budget cannot be hit twice): kept as a guard, its mutation is equivalent.

## First live run: the answer round never fired (2026-10-13 evening, M1)

- Merged `ace20de` 19:06, Odysseus restarted 21:08; chains 19:15 and 21:08. **No `tool budget (20) reached` line**, yet 5 task runs ended `budget_exceeded`: `wh_golden_typo` (Ollama, before the merge), `res_gold2000` ×3, `res_gnats` ×1, each with **23–26 rounds and 22–25 tool calls in one turn**, above both limits (20 and 20).
- **Cause:** every one of them had an approval card. Answering it starts a new `chat_stream` request with fresh limits (`routes/chat_routes.py`, one `stream_agent_loop` call), so the turn is two loops. Qwen makes about one call per round, so in the second loop the 20 calls and the 20 rounds run out together: the budget was hit **on the last allowed round**, where the first version deliberately skipped the answer round (`round_num < max_rounds`) — and logged nothing.
- **Fix (2026-10-14):** the round loop runs one round past the cap **only** for a forced answer (`budget_answer.round_allowed`); the same gap closes for the loop-breaker's answer round. Running out of rounds without a forced answer is unchanged (`rounds_exhausted`, the client's *Continue*). Tests: 11; new mutations caught — extra round removed (1 test fails), cap ignored (2), extra round without a forced answer (2); M1/M2 re-run on the new code (5 each). Sandbox suite: 8,098 passed, the same DNS-only failure.
- **Not addressed:** an approval card resets both limits, so one turn can use up to twice the budget. Separate question; recorded here only.

2. **Safety bounds, tested on the real loop with a scripted model** (pattern: `tests/test_decision_nudge.py`):
   - the forced round's request carries **no tools** (a text-only answer cannot change a document; this is the bound item 8's reverted nudge lacked);
   - at most **one** extra round, and no tool executes after the budget is hit, even if the model emits a tool call in that round;
   - budget 0 (unlimited) → behaviour unchanged; a turn that answers before the budget → unchanged (negative controls);
   - every `tool_call_id` of the cut batch gets a result.
   Check each test fails with the call site removed before it passes with it, and mutate the module (message dropped, tools left on, two forced rounds) with the scores written down.
3. **Verify (M1):** full suite; then webhard ×2 + research ×2 on Qwen/LM Studio (`bench_chain.sh qwen-web` plus `qwen`, ~1.5 h). Measure: task runs ending with no answer (13 Oct baseline: ≥ 8 of ~150), pass rate, and what the forced answers say — an honest *"I could not find …"* fails the checks but is still better than silence; a confident wrong answer is the risk to watch.
4. **Only if 3 leaves many silent turns:** an earlier, softer note (*"N tool calls left"*) a few calls before the budget. Acting on the model earlier is a bigger change; measure 1–3 first.
